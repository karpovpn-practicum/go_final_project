# Планировщик задач (TODO-лист) на Go

Итоговый проект курса Go-разработчика в Яндекс Практикуме.

## Описание

Веб-сервер планировщика задач: REST API на Go, данные хранятся в SQLite.
Готовый фронтенд в `web/` открывается в браузере и работает через этот API.

У каждой задачи есть дата дедлайна, заголовок, комментарий и, если нужно, правило повторения.
Когда задачу отмечают выполненной, разовая удаляется, а повторяющаяся
переносится на следующую дату по своему правилу:

| Правило        | Значение                                                        |
|----------------|-----------------------------------------------------------------|
| пусто          | разовая задача, после выполнения удаляется                      |
| `d 7`          | через указанное число дней (от 1 до 400)                        |
| `y`            | ежегодно                                                        |
| `w 1,4,5`      | в указанные дни недели (1 — понедельник, 7 — воскресенье)       |
| `m 1,15,-1`    | в указанные дни месяца; `-1` — последний день, `-2` — предпоследний |
| `m 3 1,3,6`    | в указанные дни только в указанные месяцы                       |

### API

| Метод и путь                        | Действие                                            |
|-------------------------------------|-----------------------------------------------------|
| `GET /api/nextdate?now=&date=&repeat=` | следующая дата по правилу                        |
| `POST /api/signin`                  | вход по паролю, ответ — JWT-токен                   |
| `POST /api/task`                    | добавить задачу                                     |
| `GET /api/task?id=`                 | получить задачу                                     |
| `PUT /api/task`                     | изменить задачу                                     |
| `DELETE /api/task?id=`              | удалить задачу                                      |
| `POST /api/task/done?id=`           | отметить выполненной                                |
| `GET /api/tasks?search=`            | ближайшие задачи (до 50), поиск по тексту или дате  |

Когда задан пароль, все `/api/task*` и `/api/tasks` требуют куку `token`.
Без неё сервер отвечает `401`, и фронтенд переходит на страницу входа.

### Структура

```
main.go              точка входа: читает TODO_DBFILE, открывает БД, запускает сервер
pkg/server/          HTTP-сервер: раздача web/, порт из TODO_PORT, подключение API
pkg/db/              схема таблицы scheduler, запросы к БД (добавление, выборка, обновление, удаление)
pkg/api/             обработчики API:
  api.go             регистрация маршрутов
  nextdate.go        NextDate() и /api/nextdate
  addtask.go         добавление задачи, проверка полей и даты
  edittask.go        получение и изменение задачи
  donetask.go        выполнение и удаление задачи
  tasks.go           список задач и поиск
  auth.go            /api/signin, JWT, middleware auth
  task.go            общий обработчик /api/task и вспомогательные функции
  response.go        JSON-ответы
web/                 фронтенд (готовый)
tests/               тесты API (готовые)
```

## Задания со звёздочкой

Выполнены все:

- [x] **Правила `w` и `m`.** Дни недели, дни месяца (в том числе `-1` и `-2`) и выбор месяцев.
- [x] **Поиск задач.** `/api/tasks?search=` ищет подстроку в заголовке и комментарии, а строку вида `08.02.2024` понимает как дату.
- [x] **Аутентификация.** Пароль задаётся в `TODO_PASSWORD`, токен JWT (HS256) хранит хэш пароля и действует 8 часов. Если сменить пароль, старые токены перестают работать.
- [x] **Docker-образ.** Сборка в два этапа, база SQLite подключается с хоста.

Сделано и то, что предлагалось как возможность:

- порт задаётся через `TODO_PORT`;
- путь к базе задаётся через `TODO_DBFILE`.

## Запуск локально

Нужен Go 1.24 или новее. cgo не нужен: драйвер `modernc.org/sqlite` написан на чистом Go.

```sh
go run main.go
```

Откройте в браузере <http://localhost:7540/>.

Если файла базы нет, он создаётся при первом запуске вместе с таблицей `scheduler` и индексом по дате.

### Переменные окружения

| Переменная      | По умолчанию   | Назначение                                          |
|-----------------|----------------|-----------------------------------------------------|
| `TODO_PORT`     | `7540`         | порт веб-сервера                                    |
| `TODO_DBFILE`   | `scheduler.db` | путь к файлу БД                                     |
| `TODO_PASSWORD` | пусто          | пароль для входа; если пусто, вход не запрашивается |

Флагов командной строки нет, всё настраивается переменными окружения.
Пример лежит в [`.env.example`](.env.example):

```sh
TODO_PORT=7540
TODO_DBFILE=scheduler.db
TODO_PASSWORD=12345
```

Сервер сам не читает `.env`, поэтому переменные нужно экспортировать в shell:

```sh
cp .env.example .env
set -a; source .env; set +a
go run main.go
```

или передать в одной команде:

```sh
TODO_PORT=8080 TODO_PASSWORD=12345 go run main.go   # → http://localhost:8080/
```

Если задан `TODO_PASSWORD`, браузер сначала откроет <http://localhost:7540/login.html>.

## Запуск тестов

Тесты обращаются к запущенному серверу по HTTP, а к файлу базы — напрямую.
Поэтому сначала запустите сервер в отдельном терминале, затем выполните из корня проекта:

```sh
go test ./tests      # тесты API
go test ./pkg/...    # юнит-тесты (NextDate, проверка задач, JWT); сервер для них не нужен
```

> `TestTasks` удаляет из таблицы `scheduler` все задачи. Чтобы не потерять свои данные,
> запускайте сервер и тесты на отдельной базе. Путь нужен **абсолютный**: тесты
> отсчитывают относительный путь от `tests/`, а сервер — от корня проекта.
>
> ```sh
> TODO_DBFILE="$PWD/test.db" go run main.go
> TODO_DBFILE="$PWD/test.db" go test ./tests
> ```

### Параметры `tests/settings.go`

```go
var Port = 7540                  // порт сервера; можно переопределить через TODO_PORT
var DBFile = "../scheduler.db"   // путь к БД относительно tests/; можно переопределить через TODO_DBFILE
var FullNextDate = true          // проверять правила w и m
var Search = true                // проверять поиск
var Token = ``                   // пусто, если сервер запущен без TODO_PASSWORD
```

Если сервер запущен с паролем, получите токен и впишите его в `Token`:

```sh
TODO_PASSWORD=12345 go run main.go
curl -s -X POST -d '{"password":"12345"}' http://localhost:7540/api/signin
# {"token":"eyJhbGciOiJIUzI1NiIs..."}
```

Токен действует 8 часов и только для того пароля, с которым он выдан.

## Docker

Образ собирается в два этапа. На первом `golang:1.24` компилирует статический бинарник для Linux.
На втором в `ubuntu:24.04` копируются только бинарник и `web/`.

Значения по умолчанию в образе: `TODO_PORT=7540`, `TODO_DBFILE=/data/scheduler.db`.
`TODO_PASSWORD` в образ не зашит, его передают при запуске.

### Сборка

```sh
docker build -t go-scheduler .
```

### Запуск

База берётся с хоста: текущая директория монтируется в `/data`, и контейнер работает
с `./scheduler.db` из корня проекта. Если файла нет, он будет создан.

```sh
docker run -d --name scheduler \
  -p 7540:7540 \
  -v "$(pwd)":/data \
  -e TODO_PASSWORD=12345 \
  -e TZ=Europe/Moscow \
  go-scheduler
```

Откройте <http://localhost:7540/>. Без `-e TODO_PASSWORD=...` планировщик работает без входа.

`TZ` задаёт часовой пояс, по которому сервер определяет «сегодня». Без него в контейнере используется UTC,
и для Москвы новый день начинается в 03:00. База часовых поясов встроена в бинарник через `time/tzdata`,
поэтому `TZ` работает, хотя в образе ubuntu нет `/usr/share/zoneinfo`.

Можно передать переменные из файла: `--env-file .env`. В этом случае `TODO_DBFILE` в `.env` должен
указывать путь внутри контейнера, например `/data/scheduler.db`, или его нужно удалить из файла.

Другой порт:

```sh
docker run -d -p 8080:8080 -e TODO_PORT=8080 -v "$(pwd)":/data go-scheduler
```

Как прогнать тесты против контейнера. На macOS тесты нужно запускать тоже в контейнере:
у файлового шаринга Docker Desktop есть задержка, и `TestTasks`, запущенный с хоста, не видит своё же удаление.

```sh
docker run --rm --network container:scheduler \
  -v "$PWD":/src:ro -v "$(pwd)":/data \
  -e TODO_DBFILE=/data/scheduler.db -e GOFLAGS=-buildvcs=false -w /src golang:1.24 \
  sh -c 'cp -r /src /tmp/w && cd /tmp/w && go test -count=1 ./tests'
```

Если контейнер запущен с `TODO_PASSWORD`, перед этим впишите токен в `Token` в `tests/settings.go`.

Остановить и удалить контейнер:

```sh
docker rm -f scheduler
```
